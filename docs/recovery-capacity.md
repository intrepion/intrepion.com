# Expanded encrypted backup and recovery capacity

The owner chose to improve recovery before the normal-account launch. The prior 20 MiB limit was below measured synthetic recovery expansion for even a few active spaces. This change raises the bounded plaintext export and recovered SQL limit to 128 MiB, with a separate 1 MiB allowance for age ciphertext overhead. Both backup verification and protected recovery use the same limit. It preserves the previously approved 5/10/15 MiB size warnings, 22-hour age alert, twice-daily schedule, seven-day all-version retention, and manual growth decisions; the higher hard ceiling is not a promise of unlimited use.

Recovery serialization counts output incrementally during estimates, iterates database rows instead of loading each table into a JavaScript array, and rejects actual recovery output as soon as it exceeds the ceiling. The estimate remains before independent ledger replay and is not a guarantee of final restore size. Encryption and decryption get a 120-second timeout; backup archive upload and download get a 180-second timeout. Existing schema validation, independent erasure and security replay, cleared sessions, disabled recovered request links and notifications, and paused invitation growth remain required.

Validation uses the already-approved encrypted backup and recovery boundary. A synthetic encrypted archive over 80 MiB restored to importable SQL with later erasure replay; the local process tree peaked around 1.15 GiB and finished in about 2.6 seconds on the owner's machine. A separate disposable local D1 exercise imported 22,501,560 bytes of recovered SQL and verified 2,399 retained records and an independently erased record absent. These are examples, not bounds on every dataset or GitHub runner. Existing marker, retention, alert, and recovery tests remain applicable, and the revised 128 MiB bound is explicitly tested.

Cloudflare documents a 5 GiB file-import limit and 100,000-byte maximum SQL statement; the serializer emits one insert per row, and the large fixture checks line sizes and local D1 import. The app limit is substantially lower than that file limit and does not change the D1 free database quota. Fourteen near-ceiling encrypted versions would occupy roughly 1.8 GiB before extra versions or other bucket usage. Monitor actual B2 storage, transaction caps, bandwidth, runner memory and duration; no trial allowance is assumed. A provider-enforced zero-dollar cap can stop a backup and is not a recovery guarantee. [Cloudflare D1 import](https://developers.cloudflare.com/d1/best-practices/import-export-data/), [Cloudflare D1 limits](https://developers.cloudflare.com/d1/platform/limits/).

Deploying this recovery change requires passing exact-revision CI, then a real monitored encrypted backup, watchdog check and isolated protected recovery rehearsal before relying on the new limit for production. Invitation launch still needs the separately reviewed normal-account safety policy, production SES access and the remaining feedback checks.
